# 규정 준수 점검표 (2차 평가·소스코드 검증 대비)

대회 **규칙 탭 원문**(2026-09-15 확인)과 부정제출 공지에 비추어 본 제출물 자체 점검 결과.

## 0. 가장 주의할 항목 — 고정 LLM 정상 호출 요건

> 규칙 2-1) "제출된 추론 코드는 평가 데이터의 **각 공고에 대해 고정 LLM 정상 호출을 1회 이상**
> 수행해야 합니다. … 모델 호출이 없거나 공고 내용과 무관한 호출만 있는 제출물은
> **제출 요건 미충족으로 무효 처리될 수 있습니다.**"

이 파이프라인은 LLM 출력이 없으면 규칙 계층으로 폴백한다. 폴백이 **전 건에서** 일어나면
점수 문제가 아니라 **무효 처리 사유**가 된다. 그래서 실행 로그에 다음 세 수치를 남긴다.

```
"모델호출": N   ← 고정 LLM 을 호출한 횟수 (= 입력 건수여야 함)
"정상응답": N   ← 그중 비어 있지 않은 응답을 받은 횟수 (= 입력 건수여야 함)
"유효JSON": N   ← 그중 JSON 파싱에 성공한 횟수
```

`정상응답` 이 입력 건수보다 적으면 그 차이만큼 정상 호출이 없었다는 뜻이다.
프로브 단계에서 구조화 출력·system 롤 설정을 바꿔가며 최대 4가지 조합을 시도하고,
그래도 0건이면 로그에 경고를 출력한다. **제출 전 반드시 이 수치를 확인할 것.**

### 2-5) 독립 예측에 대한 판단 근거 (스스로 밝혀 두는 부분)

프로브 단계는 앞 8건의 **응답이 오는지 여부**만 보고 생성 설정(구조화 출력 on/off, system 롤 형식)을
정한다. 다른 공고의 **정보·예측값·통계를 예측에 쓰는 것이 아니라** 디코딩 설정을 정하는 점검이며,
설정이 바뀌면 프로브 대상 건도 최종 설정으로 다시 생성하므로 전 건이 동일 설정으로 판정된다.
판정 로직 자체는 레코드 하나만 보고 계산한다(`extract(rec)` → `judge(facts, sig)`).
검증 과정에서 이 부분에 대한 문의가 있으면 프로브를 제거하고 고정 설정으로 재실행해도 결과는 같다.

## 3. 자산 출처

- `model/competitive_products.csv` 는 대회 제공 `data/법령패키지/중기부고시/중기부고시_경쟁제품_세부품명.csv` 의 **바이트 단위 동일 사본**이다(md5 일치 확인).
  실행 시에는 평가 서버의 `data/법령패키지/` 경로를 **1순위로 읽고**, 그 경로가 없을 때만 사본을 쓴다.
- `model/lexicon.py` 의 금액 임계값·지분율·기간 기준은 모두 `data/법령패키지/` 의 조문에서 가져왔고,
  각 상수 위에 근거 조문을 주석으로 적어 두었다. 임의로 맞춘 수치가 아니다.

## 4. 재현성

- `temperature=0.0`, `seed=20260826` 고정. 동일 입력·동일 서버 설정이면 같은 결과를 낸다.
- 규칙 계층만 돌리는 경로(`--mock`)가 있어 모델 없이도 전체 흐름과 출력 형식을 재현할 수 있다.
- `--debug-jsonl` 로 레코드별 위반 항목과 **판정 근거 문장**을 남긴다(정성평가 소명 자료).

## 5. 분석 절차의 완결성 — 스스로 지적하는 부분

- 이 파이프라인은 **고정 LLM(사실 추출) + 결정적 법령 적용 규칙**의 하이브리드다.
  LLM 출력이 없거나 깨지면 규칙 사실로 폴백하도록 설계했는데, 이 폴백이 **항상** 작동하면
  결과적으로 LLM 을 쓰지 않은 제출이 된다.
- 그래서 실행 로그에 `프로브 N/8건 유효 JSON` 과 최종 `유효JSON` 수치를 남긴다.
  **이 값이 0 이면 LLM 계층이 실제로는 동작하지 않은 것이므로, 제출 전에 반드시 확인해야 한다.**
- 2차 평가 제출 시 이 로그를 함께 제출하면 절차 완결성을 직접 보일 수 있다.
