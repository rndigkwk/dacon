# 나라장터 자체입찰 공고 법령 위반 판정 — 제출물 설명

## 1. 핵심 설계: "LLM 은 사실만, 법 적용은 코드가"

24개 항목을 LLM 에게 그대로 물으면 모델이 **조문·금액 구간·예외**까지 동시에
기억하고 계산해야 한다. 고정 모델(파인튜닝 불가) 환경에서는 이 부분이 가장 크게
무너진다. 그래서 역할을 갈랐다.

```
공고문 + 첨부 + meta
   │
   ├─(1) 규칙 계층   참가자격 섹션·금액·지역·실적·확약서 후보 추출 (정규식/사전)
   │
   ├─(2) 고정 LLM    "사실 12가지"만 구조화 출력으로 추출 (위반 판단 안 함)
   │
   ├─(3) 융합        LLM 사실 우선 + 빈 값은 규칙값 + 근거문구 원문 복구·검증
   │
   └─(4) 법령 적용   사실 + meta → 24개 항목 위반 판정 (전부 코드, 결정적)
```

LLM 에게 묻는 사실은 다음 12가지다.

| 필드 | 쓰이는 항목 |
|---|---|
| 참가자격_특정기관한정 | v1 |
| 실적제한 (해당·요구금액·발주처특정) | v2 v3 v4 v8 |
| 지역제한 (해당·제한광역목록·기초단위) | v5 v6 v7 v8 |
| 기업규모제한 (없음/소기업소상공인/중소기업자) | v11 v13 v14 v15 v16 v17 v18 |
| 중기간경쟁제품 | v10 v11 v12 v13 v14~v18 |
| 직접생산확인요구 | v10 v12 |
| 특정모델명 (+동등이상 허용) | v9 |
| 물품공급확약서 (입찰단계 요구) | v19 |
| 소프트웨어사업 (+대기업참여제한 명시) | v20 |
| 공동수급 최소지분율 | v21 |
| 설명회 (개최·참석의무·일자) | v22 v23 |
| 등록값불일치 | v24 |

## 2. 코드에 고정한 법령 기준 (data/법령패키지 스냅샷 근거)

| 기준 | 값 | 근거 |
|---|---|---|
| 고시금액(물품·용역) | 2억 3천만원 | 국가계약법 제4조①  재경부 고시(2026-439) |
| 실적제한 허용 하한 | 추정가격 ≥ 고시금액 | 국가 시행령 제21조① / 지방 시행령 제20조①3·5호 |
| 실적금액 상한 | 추정가격의 1배 | 국가·지방 시행규칙 제25조 |
| 지역제한 허용 상한 | 국가 2.3억 / 지방 5억(엔지니어링·건설기술 3.3억, 안전점검 1.5억) | 지방 시행규칙 제24조2호 |
| 지역제한 단위 | 시·도(광역), 인접 확대는 예외사유 필요 | 지방 시행규칙 제25조③ |
| 중복제한 금지 | 실적+지역 동시 제한 불가 | 지방 시행규칙 제25조⑦ |
| 기업규모 구간 | 1억 미만 = 소기업·소상공인 / 1억~고시금액 = 중소기업자 / 고시금액 이상 = 제한 불가 | 판로지원법 시행령 제2조의2① |
| 공동수급 최소지분율 | 국가 10%(하한 8%) / 지방 5%(하한 4%) | 공동계약운용요령 제9조⑤ / 지방 집행기준 제6장 제2절 |
| 설명회 일정 | 마감 전 40/20/10일, 공고는 설명일 7일 전 | 지방 낙찰자 결정기준 제7장 제3절 2-다 |
| 지방+소액수의 예외 | v2·v6·v7·v8 적용 배제 | 지방 집행기준 제5장 제3절 |
| 우선조달계약 예외 명시 | v16·v18(부재탐지) 적용 배제 | 판로지원법 시행령 제2조의3 / 공공구매제도 운영요령 제44조 |
| 경쟁제품 소기업 특례 | v11 은 기업규모 제한이 '전혀 없을 때'만 위반 | 판로지원법 제7조의2 |

중기간 경쟁제품 여부는 `model/competitive_products.csv`(중기부 고시 세부품명 616건)에
공고의 세부품명번호가 있는지로 **결정적으로** 판정한다. 번호가 없을 때만 LLM 사실을 쓴다.

## 3. 근거문구(e1~e24) 보장

- 프롬프트에서 "원문 부분문자열"을 요구하고, 받은 문자열을 `fuse.resolve_evidence` 가
  ① 그대로 탐색 → ② 공백 제거 후 위치 복원 → ③ 앞 25자 앵커로 블록 탐색 →
  ④ 문자 겹침 최대 블록 순서로 복구한다.
- 그래도 실패하면 규칙 계층이 찾은 블록으로 대체하고, 마지막에 `clean_evidence` 가
  500자 컷 + 원문 부분문자열 재검증 + `= + @` 접두 제거를 수행한다.
- 부재탐지 5항목(v10 v11 v16 v18 v20)과 비위반 항목은 항상 빈칸이다.

## 3-1. LLM 계층이 통째로 죽지 않게 하는 장치

고정 모델 환경에서 사실 추출이 조용히 실패하면 파이프라인은 규칙 폴백으로만 돌고,
점수는 규칙 단독 성능에 붙는다. 실제로 그럴 수 있는 지점을 세 곳 막아 두었다.

1. **system 롤 미지원** — Gemma 계열 chat template 은 system 롤에서 예외를 던지는
   경우가 있다. 그러면 `llm.chat()` 이 전 건 실패 → 빈 출력 → 전건 폴백.
   기본값을 **user 턴 하나로 합쳐 보내기**로 바꾸고, 템플릿이 system 을 받으면
   그때만 두 턴으로 보낸다 (`VLLMRunner._probe_system`).
2. **문법 컴파일 실패** — 스키마의 `maxLength` 등은 xgrammar 버전에 따라 미지원이라
   `StructuredOutputsParams` 생성 자체가 깨질 수 있다. 스키마에서 길이 제한을 빼고,
   생성 실패 시 비구조화 생성으로 자동 강등한다.
3. **프로브 배치** — 앞 8건을 먼저 돌려 유효 JSON 이 하나도 없으면 구조화 출력을 끄고
   다시 시도한다. 그래도 0건이면 로그에 명시적으로 경고를 남긴다.
   실행 로그의 `유효JSON` 수치가 건수와 같은지 항상 확인할 것.

## 3-2. 대회 명세를 반영한 부분

| 명세 | 반영 |
|---|---|
| 금액 구간 판단은 **공고문 기재값 우선**, 없는 값만 meta | `공고문금액`을 LLM 사실로 추출해 `est_override` 로 적용. 정규식 추출은 법령 인용문·실적요구 금액을 잘못 집어(dev 25건 중 다수) 규칙 경로에서는 쓰지 않고 초안 힌트로만 제공 |
| meta 의 `null` 과 `"미입력"` 은 다르다 | `mv()` 에서 둘 다 값 없음으로 보되 원값을 `meta` 에 그대로 넘겨 LLM 이 구분할 수 있게 함 |
| `dropped_doc_counts` 가 있으면 '없으니 위반' 단정 금지 | 프롬프트에 미수록 문서와 경고 문구를 명시. 단 v20 은 예외 — 대기업 참여제한은 공고문 참가자격 기재 사항이고, dev 의 v20 양성 5건 중 3건이 제안요청서 탈락 상태에서도 위반으로 라벨링돼 있어 면책하지 않는다 |
| 위반이 첨부에만 나타나는 항목이 있다 | 발췌는 공고문·규격서·과업지시서·제안요청서 전체에서 뽑는다 (규격 문단 별도 태그) |
| 익명화 토큰의 기관 유형·지역 계층은 판정에 사용 가능 | `[지역:rN\|단위=기초\|광역=…]` 로 v6(기초단위) 판정 |
| 평가 데이터 1,853건 | 레코드당 LLM 호출 1회 구조 — 청크 64로 배치 추론 |

## 3-3. 발췌 문단 설계 (3차 개선)

프롬프트에서 모델이 실제로 읽는 것은 규칙 계층이 골라 낸 발췌 문단이다.
dev 200건을 계측해 보니 세 가지가 어긋나 있었다.

| 계측한 문제 | 수치 (개선 전 → 후) |
|---|---|
| 태그 선점 — 먼저 붙은 `참가자격` 이 블록을 독점해 고유 태그가 사라짐 | 기업규모 1 → 332, 지역 6 → 80, 실적 3 → 15, 특정기관 1 → 11 |
| 문단의 소속 절이 사라져 '참가자격'과 '제출서류·입찰무효'를 구분할 수 없음 | 절 제목 표시 0% → 99.8% (제출서류·무효로 표시된 블록 608개) |
| 예산을 절반 넘게 버림 | 프롬프트 중앙값 4,528자 → 6,589자 (예산 12,000자) |

고친 내용은 다음과 같다.

1. **다중 태그** — 한 문단에 해당하는 태그를 전부 붙인다.
   `[기업규모·참가자격]`, `[경쟁제품·직접생산·참가자격]` 처럼 겹쳐 쓴다.
   예전에는 같은 문단이 `[참가자격]` 하나로만 나가서, 모델은 어느 문단이
   기업규모 계층 판단용인지 알 수 없었다 (dev 합계 337건이 태그를 잃었다).
2. **절 제목·출처 표시** — `[태그]<공고문 / 입찰참가자격> 본문` 형식.
   SYSTEM 프롬프트는 "제출서류 목록에 이름만 오른 서류는 요건이 아니다",
   "입찰무효 사유 설명은 요건이 아니다" 를 요구하는데, 문단만 떼어 보내면
   그 판단에 필요한 구조 정보가 없었다. `textutil.heading_index` 가
   절 제목을 뽑고 `section_at` 이 블록마다 소속 절을 찾아 붙인다.
3. **우선순위 예산 배분** — `TAG_PRIORITY` 순으로 예산을 가져가고 출력은
   문서 순서를 지킨다. 항목 수가 적어 놓치면 바로 0점이 되는 신호
   (특정기관·확약서·설명회·공동수급)를 양이 많은 참가자격보다 앞에 둔다.
4. **중복·잡음 제거** — 공고문과 첨부에 같은 문단이 겹쳐 실리면 한 번만 넣고,
   용지규격·글꼴·목차 같은 서술은 뺀다.
5. **공고문 머리 1,200 → 2,400자** — v24(등록값 대조)와 `공고문금액` 은 개요표를
   읽어야 풀리는데 1,200자에서 잘리는 공고가 있었다. 토큰 예산이 남는다
   (중앙값 4,828 / 최대 7,573 / 예산 14,272).
6. **머리표 오염 방어** — 모델이 `[태그]<…>` 까지 베껴 오면 원문 부분문자열이
   아니게 되므로, `fuse.resolve_evidence` 가 **있는 그대로 찾기에 실패했을 때만**
   머리표를 떼고 다시 찾는다. 원문에도 `[지역:r1|단위=기초|…]` 같은 익명화
   토큰이 대괄호로 시작하므로 무조건 벗기면 안 된다.
7. **브랜드 오탐 차단** — `Full HD`, `A4`, `MP4` 같은 일반 규격·포맷 표기가
   모델명으로 잡혀 v9 오탐을 만들었다. `SPEC_STOP` 에 40여 개를 추가했다.

검증한 것 — 정답 근거문구가 프롬프트 안에 들어가는 비율 **54/54 (100%)**,
규칙 단독 경로 Macro F1 **0.5756 로 불변**(회귀 없음), train 3,000건 무오류,
자가검증 PASS. 발췌는 LLM 경로에만 영향을 주므로 `--mock` 점수로는
개선폭을 잴 수 없다. 개선 근거는 위 계측치다.

## 4. 견고성

- 레코드 단위 예외 처리: 신호추출·추론·판정 어디서 실패해도 그 건만 전항목 0으로 채우고 진행.
- LLM 출력이 비거나 JSON 이 깨져도 규칙 사실로 폴백 → `--mock` 실행과 동일 경로.
- 입력 `id` 와 행 수를 그대로 따르며, 하드코딩된 ID·건수가 없다.
- 프롬프트는 토큰 예산(16384 − 900)에 맞춰 발췌 문단을 자동 축소한다.

## 5. 로컬 검증 결과

`python script.py --mock` (= LLM 없이 규칙 계층만) 으로 dev 200건 채점:
**Macro F1 0.576**, 근거문구 규약 위반 0셀. 이는 **하한선**이며, LLM 사실 추출이
붙으면 의미 판단이 필요한 항목(v1 v4 v9 v10 v12 v13 v24)에서 더 오른다.
